## 2026-08-29 公開手順を wrangler pages deploy に変更

### 何が起きたか

`soro-camp.pages.dev` が **HTTP 404** になった。ビルド（`out/`、208ページ）は正常で、
`out/index.html` は 529,523 バイト、`sitemap.xml` も `https://soro-camp.pages.dev` を指していた。

原因はダッシュボードの **ZIP アップロード経路**。ZIP で上げたデプロイは
`npx wrangler pages deployment list --project-name soro-camp` 上では **Environment=Production / Branch=main**
として存在するのに、**実ファイルが載っていなかった**。決め手は、個別デプロイURL
（`https://<id>.soro-camp.pages.dev/`）まで 404 だったこと。2日前の別デプロイも同じ状態だった。
**症状は「本文ゼロバイトの 404」**（`Content-Length: 0`、`Cache-Control: no-store`）。

同時に、**PowerShell 5.1 の `Compress-Archive` は ZIP のパス区切りにバックスラッシュ（`\`）を書く**
という別のバグも踏んでいた（実測：1,988エントリ中1,967件が `\`、`/` は0件）。
これだと `/about` `/camp/*` の詳細ページと `/_next/*` のアセットが丸ごと配られない。
ルート直下の `index.html` だけは正しく入るので、**トップだけ生きているように見えて中身が壊れる**手口になる。
ZIP をどうしても作るなら `Compress-Archive` ではなく
`[System.IO.Compression.ZipFile]::CreateFromDirectory` を使う（区切りが `/` になる）。

### どう直したか

```bash
npx wrangler pages deploy out --project-name soro-camp --branch main
```
1,986ファイルを直接アップロードして復旧（Uploaded 1848 files / 138 already uploaded）。
デプロイ `3431fdae` は Environment=Production / Branch=main。
初回は用心して `wrangler.toml` を一時退避したが、**退避は不要**だった。
`wrangler pages deploy` は `pages_build_output_dir` が無い設定ファイルを

## 2026-08-29（追加2）野営地に wildStatus を入れた

### なぜフィールドにしたか

「公認なし」の表示は `cautions` の文字列（「黙認」「公認した野営地ではない」など）を
正規表現で見て出していた。**注意事項の文言を書き直すと判定が静かに壊れ、表示が消える。**
消えても画面はエラーを出さないので誰も気づかない。

公認された無料開放地と、黙認されているだけの河川敷では**利用者が負う責任が違う**。
同じ顔で並べるのは危ないので、`wildStatus?: "公認" | "黙認" | "不明"` を持たせて固定した。

実際、文字列判定では11件中4件しか「公認なし」が出ておらず、
**裏付けの取れていない5件が公認と同じ顔で並んでいた。**

### 判定結果（active な野営地11件）

書き込みは `scripts/apply-wildstatus-2026-08-29.js`（`--write --force` の二重ガード＋整形ガード＋
既存値があれば中止する照合ガード＋wild の網羅検査）。各エントリに根拠を文字列で持たせてある。

### 「不明」は削除ではなく既定表示から外す

`hasEvidence()` の野営地分岐に `wildStatus !== "不明"` を足した。

| 「公認なし」表示 | 4 | **9** |

### `sanogawa-camp` を validate の必須チェックから外した

「不許可」のような4つ目の値を足すなら、そのとき条件も見直すこと。

`scripts/test-filters.js` に2本足した（`isToleratedWildSite` / `hasEvidence` が

「黙認」に正規表現が当たっていた**こと。判定前にコメントを除去する `stripComments` を入れて直した。
ソースを文字列で検査するテストを足すときは毎回これを踏むので注意。
