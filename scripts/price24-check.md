# 料金未確認23件の再調査（`引き継ぎ_2026-08-07.md` §7-1）

対象: `priceVerified !== true` かつ `status === 'active'`。**23件**。

引き継ぎ §7-1 では「24件」と書いてあるが、24件目は `hayakawa-camp`（早川町オートキャンプ場）で
`status: 'suspended'`（災害復旧のため数ヵ年休業）。**今行けない施設なので対象外**とした。

## この調査の前提

**batch76 調査（`batch76-check.md`）で一度探して取れなかった残り**なので、
同じ探し方（施設名＋料金でWeb検索、なっぷの料金タブ）は既に失敗している。当たる順を変えた。

| | 自治体系 | 民間 |
|---|---|---|
| 1 | 例規集の「◯◯キャンプ場条例」使用料条項 | 公式サイトの料金PDF・画像 |
| 2 | 施設予約システム（電子申請・公共施設予約） | 公式Instagram / X の固定投稿 |
| 3 | 観光協会・公園管理者のPDF | Googleマップの施設情報・口コミ内の金額言及 |

## 判定の定義

| 判定 | 意味 | データへの反映 |
|---|---|---|
| **PRICED** | 一次情報でソロ1名の総額が確定 | `priceMin`/`priceNote` 更新、`priceVerified: true`、`lastVerified: 2026-08-07` |
| **UNPRICED** | 上の全ソースを当たっても出ない | **`needsPrice: true` を立て、`priceMin`/`priceMax` を 0 に落とす。**`priceVerified` は false のまま |
| **PARTIAL** | 一部しか取れない（口コミの金額言及のみを含む） | `priceNote` に参考として書くだけ。`priceVerified` は立てない |

**UNPRICED で `priceMin` を 0 に落とす理由。** 根拠のない数字を残したままにすると、
将来 `priceVerified` を立て直した瞬間に**その数字がそのまま表に出る。**
0/0 は `CampCard` の `priceUnknown`（価格未調査）と同じ表現なので、既存の表示と整合する。
`validate-data.js` に「`needsPrice` が立っているのに `priceMin` に数字が入っていたらエラー」を入れて機械で守る。

**`needsPrice` を新設した理由。** この23件は「一度まじめに探して出なかった」記録である。
印を付けずに置くと、次に `priceVerified` で絞り込んだ人が**同じ23件を同じ手順で調べ直す**。
`needsPrice` は「調べていない」ではなく「**調べたが公開されていない**」を表す。

### `priceMin` の定義（batch76 から継続）

**ソロ1名が実際に払う総額。** 入場料・駐車料・渡船料・管理費・環境協力金を全部含む。
`priceNote` の先頭に課金方式（人数課金 / サイト単位課金 / 区画+人数）を書く。
サイト単位課金は「ソロでも定員込みの満額」と分かる書き方にする。

## 今回の教訓

### 1. 「公式サイトに料金表が無い」の半分は、探し方の問題だった

batch76 が「公式に料金表が無い」と判定していた施設のうち、**5件は実際には載っていた。**

|---|---|
| `tiny-camp-village` | **Q&Aページ**（`/general-5`） |
| `naminokomura` | 独立した料金ページ（`/price.html`） |
| `camp-akaike` | **トップページの下の方**（`#price` セクション） |
| `flora-campsite` | **BOOKINGページ**（`/booking`。`/camp-site` には無い） |
| `doshi-mori-cottage` | 施設ページの**1階層下**（`/moricote/moricote_ryokin/`） |
| `yatsugatake-oizumi` | 「**宿泊施設紹介**」ページ（`information.html`） |
| `takaranoyama-fureai` | 「テントサイト」ページ（`/tent/`） |
| `shimobe-yurucamp-sato` | **道の駅側の公式サイト**（施設名で検索しても出ない） |

**教訓: トップページを見て「無い」と判断しない。先に `sitemap.xml` かページ一覧を取る。**
料金は「料金」という名前のページにあるとは限らない。Q&A・予約案内・施設紹介に紛れている。

### 2. レンダリング結果だけを見ると、載っている料金を見落とす

`fujinomori-yamanakako` は batch76 が「なっぷの料金欄は見出しのみで金額なし」と記録していたが、
**HTMLを直接読むと完全な料金表が入っていた。**
`usami-shiroyama` も同じ経路で施設利用料の全額が取れた。

逆に、**HTMLを読んでも取れないもの**もはっきり分かれた。
なっぷの**プラン個別ページ**の金額は予約システム側にあり、日付を指定しないと出てこない。
CHILLNN・489ban・tabinoya も同様。**「施設が入稿した料金欄」と「予約システムの在庫価格」は別物。**

**教訓: 施設ページの料金欄はHTMLに入っている。プランの金額は入っていない。**
前者は raw HTML を読めば取れる。後者は諦めて別ソースへ移る。

### 3. 閉鎖した施設ほど、料金付きの情報が残り続ける

**CLOSED 2件はどちらも「料金を探していたら閉鎖が見つかった」。**

§6-4 は「名前がヒットしても実在の証明にならない」だったが、**料金でも同じ**だった。

`tiny-camp-village` は batch76 が駐車料金550円を**必須実費**として記録していたが、

`price24-check.md` に**どこを当たって何が無かったか**を1件ずつ書いてあるのはそのため。

`priceVerified` を立て直した瞬間に表に出るため。`validate-data.js` が機械で守る。

## A. closed の警告文が実態と合っていなかった

**詳細ページは closed 全件に「この場所は現在キャンプが禁止されています。訪問しないでください。」を
出していた。これが正しいのは `sanogawa-camp` だけだった。**

**2方向に間違っていた。**

- 廃止・閉業した施設に「**禁止されている**」と書くのは事実と違う。
  誰も禁じていない。事業や施設が終わっただけ
- 閉業した施設に「**訪問しないでください**」と書くと、
  **その土地に立ち入ること自体が禁じられている**ように読める

### 追加したフィールド

```ts
closedReason?: 'prohibited' | 'abolished' | 'closed_business';
closedNote?: string;   // いつ・誰が・何をしたかを1文＋出典URL
```

**3値に分けた理由は、確かめ先と復活の芽が違うから。**

| 値 | 意味 | 確かめ先 | 復活 |
|---|---|---|---|
| `prohibited` | 場所は在るが**キャンプ行為が禁じられた** | 管理者・自治体の掲示 | 方針が変われば有り得る |
| `abolished` | **公共施設として用途を廃止**した | 自治体の告知 | **戻らない**（跡地が別用途になる） |
| `closed_business` | **民間施設が営業を終了**した | 公式サイトの生死・予約サイトの表記 | 事業者が変われば有り得る |

`abolished` と `closed_business` は表示上は同じ文面だが、**次に誰かが調べ直すときの当たり先が違う**ので
データとしては分けている。

### 表示

```
prohibited                     → この場所は現在キャンプが禁止されています。訪問しないでください。
abolished / closed_business    → この施設は営業を終了しています。現地に施設はありません。
```

下に `closedNote` と出典リンクを出す。`suspended` の告知と同じ作りにした。

### 付与した内訳

| slug | closedReason | 根拠 |
|---|---|---|
| `sanogawa-camp` | `prohibited` | 南部町が河川公園として管理。公園内でのキャンプ・火気の使用は不可 |
| `hinata-camp` | `abolished` | 伊勢原市が令和6年3月に用途を廃止。跡地は「SMBCの森」 |
| `takaranoyama-fureai` | `abolished` | 都留市。土砂災害特別警戒区域の指定で令和7年度末に閉館（下記 B-2） |
| `sports-train-aokigahara` | `closed_business` | 公式ドメイン失効・なっぷ予約不可 |
| `fujigane-kogen` | `closed_business` | 2020年6月開業、現在は閉業 |

### soloComment も直した（§6-10）

**警告だけ直して本文を放置すると意味がない。**利用者が読むのは本文のほう。

| slug | 旧 soloComment |
|---|---|
| `hinata-camp` | 「大山日向薬師の麓、伊勢原の渓流沿い。**アクセス抜群で平日ソロにも最適**。」 |
| `sports-train-aokigahara` | 「青木ヶ原樹海の中の異世界キャンプ場。アウトドアセレクトショップ運営、洗練された空間。」 |

**どちらも現役として勧める文面だった。**過去形に書き直し、閉鎖の事実と理由を入れた。

`season` も直した。「7月20日〜8月31日のみ」「通年（1月・2月は冬季休業）」が
**生きた開設期間に読める**ので、「廃止（令和6年3月まで …）」「閉業（旧: …）」の形にした。

`sanogawa-camp` と `fujigane-kogen` の soloComment は既に閉鎖に触れていたので触っていない。

### validate-data.js

- `status === 'closed'` なのに `closedReason` が無い／不正値 → **エラー**
  （未設定だと表示が「禁止されています」側に落ちるので、警告では足りない）
- `closedNote` が空 → 警告。URLが無い → 警告
  ただし **`prohibited` は URL 警告から除外**した。現地の掲示や管理者への確認が根拠になりうるため
- `closed` でないのに `closedReason`/`closedNote` が残っている → 警告

**わざと壊して3種すべて発火することを確認済み。**

### 残した宿題

**`closedReason` は `closedNote` の中身と二重管理になっている。**
どちらも「なぜ閉じたか」を持つので、片方だけ直すとずれる。
今は5件しかないので手で揃うが、増えるなら `closedNote` から機械的に検査する手はある。

## C. officialUrl の死活チェックを機械化した

`scripts/check-official-urls.js` を追加。結果は `scripts/url-check-2026-08.md`。

`sports-train-aokigahara` の閉業は「公式ドメインが Wix の ConnectYourDomain Error だった」
ことで分かった。**これは Web検索なしに全件へ機械的に回せる。**

**判定するだけで `campgrounds.json` は書き換えない。**誤検出が必ず出るため、反映は人がやる。
対象は `status === 'active'` の全件で、**`lastVerified` や `priceVerified` で絞っていない**（§6-1）。

同時実行3・リクエストの開始間隔1秒・タイムアウト10秒・リダイレクト追跡あり。168件で約3分。

### 結果

| 判定 | 件数 |
|---|---|
| **DEAD** | **3** |
| **PARKED** | **0** |
| **CLOSED_HINT** | **4** |
| NO_URL | **89** |
| OK | 72 |

**`officialUrl` を持つのは 168件中 79件（47%）しかない。**
§6-9 のとおり `officialUrl` の欠落自体が「一次情報に当たっていない」の指標になりうるので、
**NO_URL 89件は次の調査対象の候補**として使える。

### この検査で見つけられない型がある

**`takaranoyama-fureai` はこの検査を素通りする。**
公式サイトは生きていて、料金ページも通常どおり動いている。閉館の告知は `/news/` にあった。
**トップページのHTMLだけでは分からない。**

同じ理由で、**JSでしか描画しないサイトは本文がほぼ空になり、告知があっても拾えない。**
4件がそれに当たる（evidence に「本文がほぼ空」と出している）。**OK は無罪の証明ではない。**

伸ばすなら、トップページのリンクから `news` / `info` / `topics` / `blog` を1階層だけ辿って
同じ語で検査する。今回は入れていない。
