# priceNote の書式は生成テンプレートの指紋になるか（2026-08-12）

`yadoriki-camp` で削除が確定した `priceNote: "大人500円+サイト500円〜"` と同じ体裁が
他にもある件の検証。**調査のみ。`data/campgrounds.json` は触っていない。**

**結論を先に: 書式は「投入バッチの指紋」としては 100% 機能するが、「捏造の指紋」としては機能しない。
この線は捨てる。代わりに副産物として出た別の信号をツール化すべき。**

## 2. `priceVerified: true` の根拠は追えるか — **追えない。循環していた**

12件すべてについて、投入時の `priceVerified` は **未設定（`null`）** だった。
true が立ったのは全12件が**同一コミット**:

```
9fd15e3 2026-08-07  hide unverified prices and neutralize their value score
```

そのコミットが使った `scripts/apply-price-verified.js` の判定は次の1行に尽きる。

> `priceNote` があるものに `priceVerified: true` を立てるだけ。

コミットメッセージにも「priceVerified を新設。**priceNote の有無で初期値を付けた**（126件 true / 76件 未設定）」とある。
判定の根拠は「料金を実際に調べた人は内訳を必ず書ける」という推定で、**個別の出典確認は一切していない。**

**これが A型では循環になる。** 生成された内訳（priceNote）の存在が、確認済みフラグ（priceVerified）の
根拠にされている。内訳そのものが疑わしいレコードでは、この推定は成り立たない。

さらに `scripts/price24-check.md`（料金未確認23件の再調査）は
**対象が `priceVerified !== true` だった**ため、A型12件は最初から調査対象外だった。
**A型は「一度も料金を人間が確認していない」まま今日に至っている。**

## 5. 判定: 書式は指紋になるか

### なる部分 — 投入バッチの識別としては 100%

A型12件・B型12件が全て5月、8月投入35件で0件。**コホート識別としては完全分離。**
「この priceNote は fb9bddc で生成された」はほぼ確実に言える。

### ならない部分 — 真偽の判定としては使えない

- A型12件のうち**5件は officialUrl か tel を持つ実在確定施設**。書式だけで疑うと**誤検出率42%**。
- B型12件は**全件が対照群**（フラグなし active・出典あり）。B型を疑う理由は何もない。
- そもそも A型/B型は日本語として自然な料金の書き方で、珍しくない。

**書式が示すのは「誰が書いたか」であって「内容が正しいか」ではない。**
5月バッチが書いた priceNote には正しいものと生成されたものが混在しており、書式では分離できない。

しかも実務上、**5月バッチの識別なら `git log -S` で直接できる**（本調査でも使った）。
書式という間接的な代理指標を作る必要がない。**この線は捨てる。**

## 6. 代わりに出た信号 — こちらはツール化する価値がある

書式ではなく **「`priceVerified: true` なのに出典（officialUrl / tel）が1つも無い」** で切ると、
はるかに素直に分離する。無料開放（`type: wild` と `priceNote: 無料開放`）は
出典が無くて当然なので母集団から外した。

**有料かつ `priceVerified: true` の 129件**での交差表:

| | 出典なし | 出典あり | 出典なし率 |
|---|---:|---:|---:|
| **A型** | **7** | 5 | **58%** |
| A型以外 | 4 | 113 | **3.4%** |

Fisher の正確検定（両側）**p ≈ 2.3×10⁻⁶**。偶然ではない。

ただしこれは「A型が怪しい」ことの証明ではなく、**「出典なし」のほうが強い判定軸である**ことを示している。
A型はその部分集合に偏って重なっているだけ。

## 7. 所見とツール化の判断

### ツール化しない: priceNote の書式検出

理由3つ。

1. **誤検出率42%**（A型12件中5件が実在確定施設）。運用に耐えない。
2. **同じことが `git log -S` でできる。** 書式は5月バッチの代理指標にすぎず、
   バッチを直接特定できる以上、代理を作る意味がない。
3. **書式は今後増えない。** 8月投入で0件なので、将来のレコードには当たらない検査になる。
   固定された過去の集合を検出するために恒久的な検査を足すのは割に合わない。

### ツール化する: 「`priceVerified: true` なのに出典が1つも無い」

`validate-data.js` に警告として足す価値がある。理由:

- 現時点で**11件**を即座に出す。うち**6件は active + フラグなし**の未発見分。
- 判定が意味論的に正しい。`priceVerified` は「一次情報で確認した」の意味なので、
  **確認先が1つも記録されていないなら、その主張は成り立たない。**
- 将来のレコードにも効く。8月投入分にも当たる（無料開放10件は除外条件で落ちる）。
- 除外条件が単純: `type: wild` または `priceNote` が無料開放系。

### より本質的な修正: `priceVerified` の意味を立て直す

**今の `priceVerified` は「priceNote があるか」の言い換えでしかない**（`apply-price-verified.js`）。
`priceNote` の有無を根拠に立てている以上、`priceVerified` は独立した情報を持っていない。
「内訳を書けた＝調べた」という推定は、内訳ごと生成されうる状況では崩れる。

立て直すなら判定基準は **「出典が記録されているか」**（officialUrl / tel / 出典URL付きのノート）で、
`priceNote` の有無ではない。ただし**126件の再判定が要る**ので、影響範囲は小さくない。
上の検査を先に入れて件数（11件）を把握してから決めるのが順当。

### この調査の限界

- 書式分類の正規表現は本調査で設計したもの。A型とB型の境界は「大人◯円+」で始まるか
  だけの恣意的な線で、別の切り方をすれば件数は動く。**分離が明確だったのは
  「5月 vs 8月」の軸であって、A型という定義の妥当性ではない。**
- 「出典なし」は officialUrl と tel の有無で判定している。
  実際には出典を持ちながらフィールドに記録していないレコードがありうるので、
  11件がそのまま捏造候補ではない。**「裏取りの手段が記録されていない」までしか言えない。**
- A型の5件（実在確定施設）の料金が実際に正しいかは確認していない。
  書式が黒の証拠にならないことを示すのが目的だったので、そこまでは踏み込んでいない。
