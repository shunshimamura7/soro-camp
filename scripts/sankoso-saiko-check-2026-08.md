## 座標 — `coordsVerified` を外した（判断が入っている）

`sankoso-auto` と違い、**逆ジオは通る。**

```
$ node scripts/check-one-coord.js --pref=山梨 "奥道志:35.47,138.944"
  逆ジオ: 山梨県 / 道志村 / −
  標高  : 903m
  判定  : OK
```

外した理由は**値の精度**。`35.47` は小数2桁で、粒度がおよそ1km ある。
**地図のピンを読めば小数6〜7桁になる**（§8 の実測値はいずれも7桁）ので、
この値は人が目視で取ったものではありえない。`coordsVerified` の定義（人が地図上で目視確認した）に合わない。

データ全体で `coordsVerified: true` の145件のうち小数2桁は5件しかなく、
そのうち `folkwood-yatsugatake` は §7-6 で既に「小数2桁で粒度約1km」として要修正に挙がっている。
**同じ水準なので同じ扱いにした。**

- `coordsVerified` を外し、`needsCoord: true`（§2-6 の用途2）
- **`coordsGsiChecked: true` は残した。**機械検証を通ったこと自体は事実で、
  人の目視とは別の記録なので消す理由が無い（§2-5）

**これは判断が入っている。**「道志村として整合しているのだから触らなくてよい」という判断もありうる。
戻す場合は `coordsVerified: true` を立て直して `needsCoord` を消せばよい。

`sankoso-auto` を直したときに `okudoshi-auto` が「住所だけの誤り」に見えていたが、
