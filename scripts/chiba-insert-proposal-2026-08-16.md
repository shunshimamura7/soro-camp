**ソースが1本も変わっていなければ、判定も変わりようがない**（`classify` は
`sourcesFor` の結果と `records` にしか依存しない）。

### ★ まとめて足すか、1つずつか — **まとめて接続。ただし走らせるのは別**

判断材料:

| | まとめて | 1市町村ずつ |
|---|---|---|
| **L1 が共有されている** | 8市町とも同じ県台帳（`pref-chiba-sports`）を使う。**台帳が壊れていれば8市町とも同時に壊れる**ので、1つずつ足しても切り分けにならない | 切り分けの効果が薄い |
| 検証の手数 | 接続の副作用は「既存18が動かないこと」1点。**上の突き合わせ1回で足りる** | 8回繰り返すことになる |
| 失敗したときの戻し | `Object.assign` の1行を消すだけ | 同じ |
| 走らせる範囲 | **接続と実行は別。**`--district` で1市町村ずつ走らせられる | — |

**接続はまとめて、実行は市町村単位で。**接続は定義の追加であって取得ではないので、
接続しただけでは何も起きない。**危ないのは実行のほうで、そちらは元から1つずつ選べる。**

### 3-4. ★ 一次情報から埋められないフィールドがある

`scores`（5軸）と `features`（焚き火・風呂・トイレ等）は、**precheck が料金と住所と電話しか
見ていないので埋まらない。**でっち上げない。

**既存の前例に揃える**（`murokubo-greenpark`。道志村・2026-08-11 追加）:

- `status: "unverified"` … 実在と料金は確認済みだが**現地の設備が未確認**
- `features` の boolean は **`false` ＋ `*Note` に「要確認」** … `false` は
  「無い」ではなく**「あると確認できていない」**の意味で使われている
- `toilet: "不明"` / `toiletNote: "要確認"`
- `soloComment: ""` … 書けることが無いなら空
- `lat: 0 / lng: 0` + `needsCoord: true` … `validate-data.js` は**0をエラーにせず別集計**する
- `scores` は **3 を基準**に、根拠のある軸だけ動かす

> **`scores` だけは前例でも埋めている**（`murokubo-greenpark` は quietness 4 / 他 3）。
> **これは判断であって一次情報ではない。**下の提案では**全軸3**にして、
> **動かした軸が1つも無いことを明示する。**
