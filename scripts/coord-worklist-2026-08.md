## 手順

1. Googleマップで**検索用文字列**を貼って検索する
2. **施設のピンを確認する。**施設名が一致しているか、
   近隣の別施設を掴んでいないかを見る
   （§6-18 のとおり、名前が似ていると別施設の情報が紐づくことがある）
3. URLの `data=` の末尾にある **`!8m2!3d緯度!4d経度`** から座標を読む
   ```
   .../data=!4m6!3m5!1s0x6019.../!8m2!3d35.5694332!4d139.1992778
                                          ^^^^^^^^^ 緯度  ^^^^^^^^^^ 経度
   ```
   **`@緯度,経度` は使わない。**あれは地図の表示中心で、
   ピンの位置とは違う（実測で約200m西にずれる）
4. slug と座標を控える

**ピンが見つからない施設は、座標を書かずに「見つからず」と残すこと。**
近そうな場所を当てて書くと §6-16 の捏造になる。

### ⚠ 住所が確定していないもの

**座標より先に住所を決める必要がある。**住所が割れたまま座標を取ると、
どちらの住所に合わせた座標なのか分からなくなる。

- `saiko-tsuhara-camp` … 住所は出典により西湖351（町観光連盟）と西湖2299（じゃらん）で割れている。要確認

## 流し込んだあとにやること

- `node scripts/verify-address-gsi.js --slug=<slug>` で **MATCH になるか確認**
  - **道志村の施設は NO_OAZA が正常。**大字を持たないので MATCH は出ない
- `needsCoord` を外す（座標が入ったレコードに `needsCoord: true` が
  残っていると「まだ取得すべき対象」という誤ったシグナルになる）
- `coordsVerified: true` を立てる（人の目視で確認した、の意味。§2-5）
- `node scripts/validate-data.js`

## この作業がなぜ人手なのか

**推測で書けないのは座標だけで、だから座標が検査の軸になっている**（§6-15）。
Google Places API はキャッシュ規約でデータに保存できないので使えない。
OSM は牧野周辺の bbox で `camp_site` が1件しか無く、本命2件とも不在だった。
**機械で埋める手段が無い。**
