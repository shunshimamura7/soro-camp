# 座標クラスタ検出レポート

生成日: 2026-08-18（`node scripts/coord-cluster-check.js` で再生成できる）

本栖湖周辺の4件がまとめて湖の真ん中を指していた件を受けて、
同じように一括投入で寄せられた塊が他にないかを洗い出したもの。

**密集していること自体は誤りではない。** 同じ湖畔や谷筋にキャンプ場が並ぶのは普通にある。
妥当な密集か、寄せられた塊かを判断できる材料を並べるところまでをこのレポートの範囲とする。

## 条件

- 施設間の距離が **2km 以内**なら隣接とみなす
- 隣接でつながった塊の構成数が **3件以上**なら報告する
- 単連結でまとめるので、谷筋に沿って数珠つなぎになった塊も1つになる。
  実際に固まっているのか帯状に伸びているのかは「最遠ペア」を見て判断する
- 座標が 0,0 の件（座標未取得）は、全部が同じ点に集まってしまうので対象外

## 判断の手がかり

| 手がかり | 意味 |
|---|---|
| 最も近いペアが 100m 未満 | 別施設としては近すぎる。同一地点へ寄せられたか、二重登録の疑い |
| 市区町村が揃っていない | 隣接自治体にまたがるだけのこともあるが、寄せられた塊のサインにもなる |
| 座標の小数が3桁以下 | 手で丸めた値の疑い。小数3桁は約100mの粒度 |
| GSI検証を通っていない件を含む | 塊ごと壊れている可能性
| 全件が目視未確認 | 誰も地図上で見ていない塊 |

`nakatsugawa-camp` は住所も連絡先も持たず、コメントの内容は野営地側とほぼ同じ場所を説明している。
**同一地点の二重登録の疑いが強い。** 座標が一致しているのは、片方をもう片方からコピーしたためではないか。

`scripts/duplicate-check.js` は `coordsVerified !== true` の件だけを総当たりする作りなので、
**両方に `coordsVerified: true` が立っていたこのペアは検出対象から外れていた。**
同じ理由で見逃されているペアが他にもありうる。重複チェックの対象条件を見直したい。

### 5. 妥当だった密集の例

すべての塊が疑わしいわけではない。たとえばクラスタ5。

- `norolodge`（青野原931）と `aonohara-auto`（青野原918-1）が **100m**、`shindo`（寸沢嵐2362）が300m台
- 地番が隣同士で、相模川沿いに実際に並んでいる。GSIも3件とも OK

100m以内という手がかりが付いても、住所を見れば妥当と分かる。**距離だけで機械的に判定せず、住所と突き合わせる**のがこのレポートの使い方になる。
