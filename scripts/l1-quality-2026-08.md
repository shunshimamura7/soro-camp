## 2. PARKED_PATTERNS を直した

`check-official-urls.js` に**第2段**を足した。既存13語の完全一致は**消していない**。

```js
PARK_SUSPEND     = /account suspended|このサイトは現在準備中|サービス提供を終了|
                    connectyourdomain|domain (?:has )?expired|ドメインの有効期限が切れ/i
PARK_MARKETPLACE = /afternic|sedo\.com|dan\.com|godaddy|hugedomains|bodis|porkbun|
                    お名前\.com|エックスサーバー|さくらのレンタルサーバ|ムームードメイン/i
PARK_SELL        = /buy[-\s]it[-\s]now|buy this domain|domain (?:name )?(?:is )?for sale|
                    premium domain|make an offer|ドメインの有効期限|…/i
```

判定は3段:

1. `PARK_SUSPEND` に当たれば即 PARKED
2. **`PARK_MARKETPLACE` と `PARK_SELL` の両方**に当たれば PARKED ← 主判定
3. `PARK_SELL` だけでも**本文が20,000字未満**なら PARKED

**単独の語では判定しない。**`for sale` や `GoDaddy` 単体で切ると、
フッタの「Powered by GoDaddy」や売店案内の「Items for sale」で誤爆する。

### 偽ゼロ検証 — `scripts/.mock-parked-test.js`（15件 OK）

**両方向で見た。陰性のほうが重い**（誤爆すると生きている施設を「閉業」と誤判定してデータを壊す）。

```
■ 陽性
  ✅ 峰山の .com（GoDaddy/Afternic）が PARKED — マーケットプレイス名+売却文言
  ✅   ★ 旧判定（完全一致13語）は素通りしていた
  ✅ 日本語の売却ページ / Account Suspended / 薄い売却ページ も PARKED
■ 陰性（実測した本物の文面）
  ✅ 稲ヶ崎オートキャンプ が PARKED にならない
  ✅ オートキャンプ・フルーツ村 が PARKED にならない
■ 陰性の罠
  ✅ フッタが「Powered by GoDaddy」でも PARKED にならない
  ✅ 本文に「for sale」があっても厚いページなら PARKED にならない
■ 実ファイル
  ✅ 実物の forestpartymineyama.com（2,432字）が PARKED / 旧判定は素通り
```

`check-official-urls.js` に `require.main === module` のガードと
`module.exports = { classifyParked, … }` を足した（**require しただけで全件を叩かない**ため）。

## 4. 「内」バグと robots.txt が403のオリジン — **どちらも案Cを待つ理由が無い**

### ① 「内」バグ — 直した場合の影響を実測した

現行 `.replace(/(?:地内|地先|先|内)$/, '')` → 提案 `.replace(/(?:敷地内|地内|地先)$/, '')`

| 対象 | 地区キーが変わる件数 |
|---|---|
| **既存188件** | **1件**（`sessokyo-camp`） |
| 千葉の L1 41件 | **0件** |
| 千葉の候補36件 | 1件（大多喜SABO が `堀之` → `堀之内` に**直る**） |

唯一動く `sessokyo-camp` は
`榛原郡川根本町犬間長島公園敷` → `榛原郡川根本町犬間長島公園` で、
**`inDistrict` は前方一致なので「犬間」との突き合わせは変わらない。**

→ **実質的に既存の突き合わせを1件も壊さない。**

### ② robots.txt が403のオリジン

現状 `getRobots` は `res.ok` でなければ「制限なし」に倒すので、
**robots.txt を403で拒否しているサイトを1秒間隔で叩き続ける。**

実測で該当するオリジン:

| オリジン | robots.txt | 本体 | 影響 |
|---|---|---|---|
| `japancamp.jp` | 403 | 403 | **既存3県の `PREF_SOURCES` 全部** |
| `seiwanomori.jp` | 403 | 403 | 千葉・清和県民の森 |
| `kazusa-autocamp.com` | 403 | 403 | 千葉・かずさ |
| `1059dai.com` | **200**（`Crawl-delay: 5`） | 403 | 千葉・千石台。**robots だけでは分からない型** |

案（実装していない）: `getRobots` の戻りに `forbidden: true` を足して、
`fetchPage` が `SKIPPED_ROBOTS` 相当で止める。
**いま `FORBIDDEN` になっているものが `SKIPPED_ROBOTS` に変わるだけで、
どちらも「測っていない」なので取得結果は変わらない**（無駄なリクエストが減る）。

### 判断材料のまとめ

| | 案Cとの依存 | 既存データへの影響 | 入れないと困ること |
|---|---|---|---|
| **「内」バグ** | **無い**（大字の切り出しであって、地区の作り方の話ではない） | **既存1件・実質0** | 大多喜SABO の地区が `堀之` のまま md に出続ける |
| **robots 403** | **無い**（取得層の話） | **無い**（FORBIDDEN → SKIPPED_ROBOTS に変わるだけ） | 拒否しているサイトを叩き続ける |

**どちらも先に入れられる。**理由:

1. **案Cとの依存が無い。**「内」バグは `splitAddress` の大字**抽出**、
   案Cは大字を**どう地区にするか**。触る場所が違う
2. **影響が測れていて、しかも小さい。**上の表の数字は実測
3. **案Cは千葉のレコード投入待ちでもある**ので、いつ決まるか分からない。
   その間ずっと `堀之` が md に出るのと、拒否サイトを叩き続けるのは、どちらも損

**逆に、同じコミットに入れる理由があるとすれば1つだけ:**
「内」バグを直すと `sessokyo-camp` の地区キー文字列が変わるので、
**案Cで地区の作り方を変えた差分と混ざって、どちらが原因か切り分けにくくなる。**
これを避けたいなら、**「内」バグを先に単独で入れて1回スイープを回し、
差分が1件だけであることを確認してから案Cに進む**のが一番切り分けやすい。

**推す順番: ①「内」バグを単独コミット → ② robots 403 を単独コミット → ③ 案C。**
