## 4. ★ 見つけた `normalizeName` のバグ（**直していない**）

```
normalizeName('CAMPGROUNDS')  → 's'     ⚠ 末尾の s が残る
normalizeName('CAMPGROUND')   → ''      正常
normalizeName('キャンプグラウンド') → ''  正常
```

`GENERIC_WORDS` に `'campground'` はあるが **複数形の `'campgrounds'` が無い。**
長いものから順に消す作りなので `campground` が先に消え、**`s` だけが固有名として残る。**

実害: `sotosotodays CAMPGROUNDS 山中湖みさき` の正規化結果が `sotosotodayss山中湖みさき` になる
（`sotosotodays` の `s` と連結して s が2つ）。**今回は両側とも同じ変換を受けるので一致するが、
片側だけ複数形のソースが出てきたら黙って外れる。**

**直していない理由**: `normalizeName` は `district-sweep.js` の全バケットの基礎なので、
**変えると26市町村ぜんぶの MISSING / IN_DATA / ORPHAN が動く。**
§18-6 のとおり**共通化・正規化の変更と、データの変更を同じコミットに混ぜない。**
直すなら単独で、**変更前後のバケット差分を実測してから。**

## 5. `camp-baird` — **解決できなかった。何が足りないかを書いて止める**

### 5-1. 何が保留になっていたか

`batch-2026-05-27-check.md` §4-5 と §328 のとおり、**保留は料金**（名称でも住所でもない）。

> 入場料（20歳以上1,200円）＋区画使用料の合算で、**区画使用料が取れていない。**
> `priceMin: 4,500` の裏が取れていないが、今回は触っていない（`priceVerified` も外していない）。

### 5-2. 今回やったこと

| 項目 | 結果 |
|---|---|
| 住所 | **確認できた。**施設公式が「静岡県伊豆市大平1052-1」＝ DB と一致（https://bairdbeer.com/ja/pages/camp-baird ） |
| 名称 | **割れていない。**施設公式・伊豆市観光とも「キャンプベアード」 |
| 営業期間 | 施設公式に「通年営業・定休日あり（サイトタイプにより異なる）」＝ DB の `season: 通年` と整合 |
| **料金** | **取れなかった** |

### 5-3. なぜ取れないか — **施設公式が料金を予約サイトへ委譲している**

施設公式のキャンプページには**料金表が無い。**
「以前の英語予約ページは閉じた。今後はなっぷから予約してほしい」とだけ書いてあり、
**料金はなっぷ側にしか無い。**そのなっぷは料金セクションが **JS 描画で取得できない**
（`https://www.nap-camp.com/shizuoka/14084` の「料金情報」は枠だけで数値が入らない）。

第三者の記述も割れている。

| 出典 | 記述 |
|---|---|
| 二次情報A | サイト利用料（場所代）＋ **1名1,000円の施設利用料** |
| 二次情報B（旧調査） | **20歳以上1人1,200円の入場料** ＋ 区画使用料 |

**金額も名目（施設利用料／入場料）も一致しない。**§20-1 のとおり内訳から逆算もしない。

### 5-4. 足りないもの（これが揃えば決まる）

1. **区画使用料の一次情報**（`priceMin: 4,500` の裏）
2. **施設利用料か入場料か、名目と金額**（1,000円説と1,200円説の決着）
3. ソロ1名・車1台の**総額**

**電話 0558-73-1225 でしか確定しない。**（施設公式が料金を持っていない以上、Web ではこれ以上進まない）

### 5-5. ⚠ あわせて記録 — `priceVerified: true` が裏の無いまま立っている

`camp-baird` は `priceVerified: true` / `priceMin: 4500` / `priceNote: "サイト4,500円〜（車込み）"` だが、
**上のとおり 4,500 の出典が無い。**これは **§17-3 の `priceVerified` と同型**
（生成された値が確認済みフラグの根拠になっている状態）。

**今回は触っていない。**しゅんの指示は「解決できるなら解決、無理なら足りないものを明記して止める」で、
`priceVerified` を外すのはその範囲を超えるため。
**外すなら `validate-data.js` の警告が1件増える**（`priceNote` があるのに `priceVerified` が無い型）ので、
`batch-2026-05-26-check.md` §4-3 の「意図的に立てていない5件」と同じ扱いに揃えるのが筋。
