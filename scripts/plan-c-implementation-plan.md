## 1. 未決の1点 — 重なり9件を (a)/(b) どちらにするか

### 1-3. ★ 結論: **どちらも要らない。案Cで構造的に消える**

案Cは地区を**市町村単位**にする。すると:

- **大字を持つ地区が1本も無くなる** → 包含ペア **7組 → 0組**
- **包含由来の二重計上 12件 → 0件**

**(a)/(b) はどちらも「76地区のまま運用する場合」の対処で、案Cを採るなら不要。**

**ただし1つ注意がある。** 残りの重複18件（同じ地区の中の同名別バケット）は
**案Cでも消えない。**あれは名前の正規化の問題（§3 の「ローマ字表記とかな表記で別バケットに割れた」型）で、
地区の粒度とは無関係。**案Cの効果を測るときに、この18件を混ぜて「減っていない」と読まないこと。**

### 1-4. もし案Cを採らないなら

**(b) を推す。**(a) は地区 md を7本失う。
`sweep-南都留郡道志村長又.md` は大字単位で見たときの記録として価値があり、
**判定に使わないだけなら残すほうがよい**（案Cの「大字は検査として残す」と同じ思想）。

## 2. ★ 先に決めること — 「市町村単位」は 18 か 20 か

**計画に入れる前に、ここを決める必要がある。**

| 単位 | 地区数 | 中身 |
|---|---:|---|
| **A: MUNI_SOURCES のキー単位** | **18** | 相模原市（緑区+中央区）/ 静岡市（葵区+清水区）を**1つ**にする |
| B: 区を分ける | 20 | 相模原市緑区 / 相模原市中央区 / 静岡市葵区 / 静岡市清水区 を別に |

**A を推す。**理由:

- **ソースが MUNI_SOURCES のキー単位で登録されている。**案Cの狙いは「ソース単位で突合する」ことなので、
  ソースの単位と地区の単位が一致するのが素直
- 区を分けると、`jalan('22101', '静岡市葵区')` と `jalan('22103', '静岡市清水区')` が
  同じエントリに同居しているので、**どちらの区の地区にも両方のソースが付く**。
  結局区の境界は効かない
- §19-5 の試算（b2 7,291 → 1,352）は **18地区**で計算されている。**基準線と揃う**

**B の利点**は、相模原市緑区（山側）と中央区（市街）で施設の性格が違うこと。
ただし**判定の粒度としては効かない**（同じソースを見るので）。

### ステップ2 — 大字検査を**同じコミットで**入れる

**§19-5 の前提条件。**市町村単位にすると大字の制約が外れ、
**名前だけで市内のどのレコードにも当たれるようになる**ので、**新しい誤突合が生まれる。**
5件中3件が案C自身が作った/残した誤突合だった。

**設計の注意**: 大字検査は**もう一度大字単位でスイープすることではない。**
それをやると §1-1 の包含問題が検査側に復活する。

```
検査の作り方:
  突合が成立した (ソース項目, レコード) の組について、
  ソース項目の住所の大字  と  レコードの住所の大字  を比べる。
  違えば「大字が違う」として md に出す。**判定には使わない。**
```

**壊れうるもの**:

- 大字が取れない項目（`nameOnly` のソース）は検査対象外になる。
  **「検査に出なかった＝正しい」ではない**ことを md に書く
- 前方一致の扱い（`麓` と `麓朝霧`）。**包含は無害**として分ける（`banchi-mismatch` と同じ）

**偽ゼロ検証に通すもの**:

- **ペンギン村（猪之頭）→ `eichinomori`（根原71-3）が検査に出ること。**
  これは案Cが新たに作る誤突合として §19-5 に記録されている**既知の答え**
- **K's CAMP伊豆高原グランピング（富戸）→ `izukogen-auto`（池672）も出ること**
- 田貫湖（猪之頭）→ `tanukiko`（佐折634-1）は**正しい突合**なので、
  検査に出たうえで「同一施設・ソース側の住所が古い」と読めること
- 無害の2件（ヴィレッヂ白州 / 朝霧CampBaseそらいろ）が**包含として分類される**こと
