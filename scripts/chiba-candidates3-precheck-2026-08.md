## 4. 403 を「取れなかった」として記録する仕組み — **無い。方針を出す**

### 現状（コードを読んだ結果）

`fetchPage` は理由を**分けて**持っている（`district-sweep.js:236-243`）:

```
''              取れた
HTTP_404 ほか   そこに無い（再試行しない）   ← 403 はここ
RATE_LIMITED    429。「無い」ではなく「測れていない」
UNREACHABLE:…   DNS・接続・タイムアウト
SKIPPED_ROBOTS  robots.txt で止めた
```

**問題は `collectSource` の集約側**（`district-sweep.js:1795`）:

```js
const status =
  listOk === 0
    ? (fetched.some(f => f.note === 'SKIPPED_ROBOTS') ? 'SKIPPED_ROBOTS'
      : rateLimited.some(f => !f.detail) ? 'RATE_LIMITED' : 'UNREACHABLE')
    : 'OK';
```

**403 は `UNREACHABLE` に落ちる。**DNS が消えた TAKIBI・柿山田と、
**サイトは生きていて ClaudeBot だけ拒否している japancamp・清和・千石台・かずさが同じ箱に入る。**

さらに `incompleteNote()` は `rateLimited` しか集計しないので、
**403 は「結果が不完全」の注記にも出ない。**

### 実測されている403（千葉だけの話ではない）

| ドメイン | robots.txt | 本体 | 影響 |
|---|---|---|---|
| `japancamp.jp` | 403 | 403 | **既存3県の `PREF_SOURCES` が全部取れていない** |
| `www.seiwanomori.jp` | 403 | 403 | 清和県民の森の料金が取れない |
| `www.1059dai.com` | **200**（`Crawl-delay: 5`） | 403 | 千石台の料金が取れない |
| `www.kazusa-autocamp.com` | 403 | 403 | かずさの実在判定ができない |
| `holywoodscamp.jimdofree.com` | — | 403 | ホウリーウッズ |

**`1059dai.com` が示すのは、robots.txt が通っても本体が403になる**ということ。
robots だけ見て「取っていい」と判断するのは足りない。

### 方針（実装はまだ）

**RATE_LIMITED と同じ格で `FORBIDDEN` を1つ足す。**理屈も同じ
——「そこに無い」ではなく「**こちらが測ることを許されていない**」。

1. **`collectSource` の status に `FORBIDDEN` を追加**
   `listOk === 0` かつ 403 が1件でもあれば `FORBIDDEN`。
   判定順は `SKIPPED_ROBOTS` → `FORBIDDEN` → `RATE_LIMITED` → `UNREACHABLE`
   （robots で自分から止めたのが最優先、次に先方が明示的に拒否、次に測れなかった、最後に届かない）
2. **`incompleteNote` を `rateLimited` 専用から一般化**して 403 も数える。
   いまの `{total, list, detail, urls}` の形はそのまま使えるので、
   `rateLimited` を `blocked: {rateLimited:[], forbidden:[]}` に広げる形が素直
3. **md の表記を分ける。**`UNREACHABLE:0件` と `FORBIDDEN:0件` が別に見えること。
   **`FORBIDDEN` は0件と読ませない**（RATE_LIMITED と同じ扱い）
4. **429 と違って再試行しない。**403 は待っても変わらない。`RATE_LIMIT_MAX_ATTEMPTS` の対象外のまま
5. **robots.txt 自体が403のオリジンは、そのオリジンごと `FORBIDDEN` にして踏まない**方針を推す。
   いまの `getRobots` は `res.ok` でなければ「制限なし」に倒すので、
   **robots を403で拒否しているサイトを1秒間隔で叩き続ける。**
   RFC 9309 上は 4xx を「制限なし」と読んでよいが、
   **403 は「あなたには見せない」という明示なので、礼儀としては止めるほうを採りたい**
6. **UA 偽装はしない。**japancamp を Mozilla で叩けば200が返るのは確認済みだが、採らない
7. **ドメイン販売ページ（峰山型）は403とは別問題。**200 が返るので status では捕まらない。
   `check-official-urls.js` 側に「本文にドメイン販売の常套句があれば DEAD 扱い」を足すのが筋

**実装していない。**案Cのコミットとは独立なので、いつ入れてもよい。
