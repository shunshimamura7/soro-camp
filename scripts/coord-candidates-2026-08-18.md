# 追記 — `mobility-park-izu` の誤った座標を地図から下ろした（2026-08-18）

## ★ 方針（1行）

> **誤りと確定した座標は、正しい値が無くても残さない。**
> **正しい値が無いことより、間違った値が出ていることのほうが害が大きい。**

現在値 35.0641 / 138.9267 は逆ジオが**静岡県函南町/日守**を返し、address と **10.6km** ずれている。
**誤りは確定していて、正しい値だけが未確定。**それでも `status: active` なので
**一覧地図にピンが立ち、周辺施設リンクが無関係な土地を指し、JSON-LD の `geo` にも流れていた。**

## `lat/lng` は null にも 0 にもしていない — **表示側で落とした**

指示の「null を許さない設計なら地図に出さない側で対処」を採った。理由は2つとも設計上の制約。

| 案 | 採らなかった理由 |
|---|---|
| `null` | **型が許さない。**`lib/types.ts` は `lat: number` / `lng: number`。`validate-data.js` も「lat/lng が数値でない」を**エラー**にする |
| `0, 0` | **意味が衝突する。**`lib/types.ts` の `needsCoord` が明記するとおり、0 は「**まだ取得していない**」の印。誤りと判明したものを 0 で潰すと**両者が区別できなくなる**（現に `needsCoord: true` の既存5件は全部 0,0 の未取得） |

**採った形**: データは**誤った値を保持したまま** `needsCoord: true` を立て、**表示側だけ止める。**

### 判定を1か所に集約した

`lib/camp.ts` に `hasUsableCoord()` を新設し、**座標を出す4か所すべてをそこに通した。**

```ts
export function hasUsableCoord(c) {
  return c.lat !== 0 && c.lng !== 0 && c.needsCoord !== true;
}
```

| 直した箇所 | 何が出なくなるか |
|---|---|
| `lib/map-style.ts` `toPinFeatures()` | **一覧地図のピン**（MapView / MapModal 共通） |
| `components/MapView.tsx` | ポップアップの「周辺施設」リンク |
| `components/MapModal.tsx` | 同上 |
| `app/camp/[slug]/page.tsx`（2か所） | 詳細ページの「🛒 周辺施設を探す」と、**JSON-LD の `geo`** |

**以前は 4か所に `c.lat !== 0 && c.lng !== 0` が直書きされていた。**
条件を足すときに**直し漏れた箇所だけが誤った位置を出し続ける**形だったので、判定を1本にした。

## 副産物 — 整形ガードが CRLF を掴んだ

apply スクリプトの整形ガードが最初に**中止**した。原因は**データの中身ではなく改行コード**で、
この日の途中で行った `git stash` / `git checkout` の往復により
**working copy が CRLF に変換されていた**（`core.autocrlf=true`）。

`git diff` は空（＝**コミット済みの内容は無事**）だったので、LF に正規化してから当て直した。

**教訓: 往復一致のガードは、中身が同じでも改行コードで落ちる。**
落ちたときは**まず `git diff` が空かを見る。**空なら内容は無事で、直すのは改行だけ。
